# Mac Sai Website Implementation Plan

**Goal:** A fast, elegant, multilingual website for Mac Sai that ranks for the searches people already use to find it and turns visitors into downloads.

**Why:** Google is the largest referrer to the repo (about 1,430 unique visitors in 14 days), but the repo's homepage field points back to GitHub. A real site can rank for feature and comparison searches in 13 languages, most of which have little competition.

**Architecture:** A static Astro site in `website/`, built and deployed to GitHub Pages by a GitHub Actions workflow. Zero JavaScript by default, self-hosted fonts and images, no analytics, no cookies, no third-party requests. The app version and download link come from `VERSION` at build time.

**Hosting:** `https://iliyami.github.io/MacSai/` for now. One config value (`site` + `base`) switches it to a custom domain later.

## Global constraints

- No em dashes anywhere in site copy.
- No analytics, trackers, cookies, external fonts, external scripts or third-party embeds. The site must practice the app's zero-telemetry promise.
- No fake testimonials, ratings or review counts. Only real, sourced numbers (downloads, stars, languages, modules).
- No competitor logos or trade dress. Comparisons are factual and dated.
- Sponsor prices are never published.
- Every claim about a feature must match the app as of 1.32.0.
- Bump `VERSION` and `MCConstants.appVersion` (patch) in the website PR.

## SEO

- A unique title (under 60 characters) and description (under 155) for every page, with canonical URLs.
- `hreflang` alternates between localized home pages, plus `x-default`.
- JSON-LD: `SoftwareApplication` (free offer, macOS 14+, version, download URL), `FAQPage`, `BreadcrumbList`, `Organization`.
- Open Graph and Twitter cards with a 1200x630 image.
- `sitemap-index.xml` (with i18n alternates), `robots.txt`, `llms.txt`.
- Semantic HTML (one `h1` per page, landmarks, alt text).
- Core Web Vitals: AVIF/WebP responsive images, preloaded hero font, explicit image sizes (no layout shift), no render-blocking third parties.

## Visual design

- The brand comes from the app icon: a deep indigo night, a violet-to-cyan crescent, and a broom with sparkles.
- Dark-first, with a light theme that follows the system.
- Higgsfield artwork: hero art (a crescent of light sweeping stardust across a night sky), soft section backdrops and the OG background. All are compressed to AVIF/WebP, and decorative images get empty alt text.
- Real, freshly captured 1.32.0 screenshots of the app in English. These are the truth of the product, so the site never uses AI images to depict the app.
- `prefers-reduced-motion` is respected, and the layout works at 320px.

## Tasks

1. **Release v1.32.0.** Tag, wait for the Release workflow, curate the notes, dispatch "Publish curated update feed".
2. **Assets.** Capture app screenshots with deep links. Generate Higgsfield art, then optimize both.
3. **Scaffold.** Astro + sitemap, base layout, SEO component, design tokens, self-hosted fonts.
4. **English pages.** Home, features hub plus six feature pages, comparison, download, privacy, 404.
5. **Localized home pages.** Strings for 12 languages (from the README translations), RTL for Farsi, hreflang.
6. **Deploy.** `website.yml` workflow (build on PRs, deploy on main and on release), enable Pages, set the repo homepage, link the site from the README.
7. **Verify.** `astro check`, production build, link check, Lighthouse (performance, accessibility, SEO, best practices), visual checks at desktop and phone width in light, dark and RTL.
8. **PR.** Version bump, full local gate, PR with screenshots.
